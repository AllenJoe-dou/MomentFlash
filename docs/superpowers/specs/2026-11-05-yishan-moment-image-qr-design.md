# 一闪 Moment 图片展示与二维码功能改进设计

日期：2026-11-05
状态：设计已确认，待用户审阅后进入实现

## 1. 改进目标

调整图片展示职责并增加二维码分享功能：

1. 图片上传和设置仅属于操作人员。
2. 参与者页面只展示操作人员指定的图片，不提供参与者上传或选择图片的交互。
3. 操作人员完成页面设置后，可以生成并保存指向参与者页面的二维码。
4. 桌面端和移动端必须完整展示图片，不裁剪、不变形、不产生横向溢出。

## 2. 角色与页面职责

### 2.1 参与者页面 `/`

保留：

- 操作人员指定的完整展示图片
- 动态液态玻璃背景
- 文本栏
- 单选/多选选项栏
- 提交按钮
- 提交成功反馈

删除：

- 图片上传区域
- 拖拽上传交互
- 预设图片选择区域
- 图片清除按钮
- 参与者侧图片选择状态

参与者不能修改展示图片。

### 2.2 操作人员配置页面 `/admin/edit`

保留：

- 页面标题与说明
- 背景设置
- 文本栏和选项栏配置
- 预设图片管理

新增：

- 上传展示图片
- 将任意预设图片设为正式展示图
- 明确标记当前展示图
- “生成二维码”按钮
- “保存二维码”按钮

### 2.3 操作人员提交记录页面 `/admin`

保持现有提交查看、筛选、详情展开和 CSV 导出功能不变。

## 3. 图片数据模型

`data/config.json` 增加：

```json
{
  "displayImageId": "plum-window"
}
```

规则：

- `displayImageId` 必须对应 `images` 数组中的某个 `id`。
- 操作人员删除当前展示图时，自动选择剩余图片中的第一张。
- 所有图片被删除时，参与者页面显示优雅的空状态，不显示破损图片。
- 上传的新图片由操作人员决定是否设为展示图。
- 参与者提交记录仍保存当时使用的展示图片信息，便于管理页追溯。

## 4. 图片完整展示规范

参与者页面图片区域使用响应式完整展示方式：

- 桌面端使用 `object-fit: contain`。
- 移动端使用 `object-fit: contain`。
- 禁止使用 `object-fit: cover` 裁剪正式展示图。
- 图片不得通过 `width` 或 `height` 强制变形。
- 图片容器保留柔和玻璃背景和留白，完整图片位于中央。
- 图片区域的最大高度：
  - 桌面端约 `720px`
  - 移动端约 `62vh`
- 图片自然比例优先；超出高度时等比缩小。
- 图片加载前显示稳定的占位区域，避免页面跳动。
- 页面在 `320px` 至桌面宽屏范围内不得产生横向溢出。

## 5. 二维码功能

### 5.1 地址规则

二维码自动编码当前站点的参与者首页：

```text
<当前页面 origin>/
```

示例：

- 本地运行：`http://localhost:3000/`
- Railway 部署：`https://你的域名/`

二维码不得包含 `/admin` 或 `/admin/edit`。

### 5.2 生成方式

采用服务端本地二维码生成：

- 增加 npm 依赖 `qrcode`。
- 新增 `GET /api/qr.png?text=<encoded-url>`。
- 服务端生成 PNG。
- 默认尺寸为 `1024 × 1024`，保证保存后清晰。
- URL 仅允许 `http` 或 `https`。
- 非法地址返回 `400`。
- 不调用第三方二维码 API。

### 5.3 操作台交互

- “生成二维码”：
  - 读取 `window.location.origin`。
  - 生成参与者首页地址。
  - 请求 `/api/qr.png`。
  - 在操作台展示二维码预览和编码地址。
- “保存二维码”：
  - 下载当前生成的 PNG。
  - 文件名固定为 `yishan-moment-qr.png`。
  - 未生成二维码时，先自动生成后再保存。
- 二维码面板必须清楚展示实际编码地址，方便操作人员核对。

## 6. 管理端图片编辑

每张图片显示：

- 图片名称
- 图片地址
- 图片预览
- 上移、下移、删除
- “设为展示图”

当前展示图显示：

- 明显的“当前展示图”标记
- 与普通预设图片不同的边框状态

## 7. API 变化

- `GET /api/config`：响应包含 `displayImageId`。
- `PUT /api/config`：保存 `displayImageId`，并验证该 ID 存在；无效时自动使用第一张图片。
- `GET /api/qr.png`：新增二维码 PNG 生成接口。
- `POST /api/submissions`：参与者的提交不再接收自定义上传图片；使用配置中的 `displayImageId` 保存展示图片。
- `POST /api/upload`：仅由管理页面调用，用于配置展示图片。

## 8. 验收标准

- 参与者页面不显示图片上传、拖拽或预设选择。
- 参与者页面始终显示操作人员指定的展示图片。
- 操作人员可上传图片并切换正式展示图。
- 参与者页面桌面端完整展示图片，不裁剪。
- 参与者页面移动端完整展示图片，不裁剪。
- 320px、390px、768px 和 1440px 宽度无横向溢出。
- “生成二维码”生成当前参与者首页地址。
- 二维码可以被手机扫码识别。
- “保存二维码”下载 `yishan-moment-qr.png`。
- 本地与 Railway 域名都能自动生成正确地址。
- 提交、管理查看和 CSV 导出继续正常工作。
- 自动化测试和浏览器测试全部通过。
